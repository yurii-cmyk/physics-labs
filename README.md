## Крок 1. Завантажити HTML на GitHub Pages

1. Відкрийте репозиторій `physics-labs` на GitHub (акаунт `yurii-cmyk`).
2. Через веб-інтерфейс (Add file → Upload files) завантажте `.html`-файл
   лабораторної (наприклад, `lab1-2-el-magn.html`).
3. Файл стає доступним за адресою
   `https://yurii-cmyk.github.io/physics-labs/<назва-файлу>.html`.
4. Додайте це посилання в Google Classroom як **Link**, а не як файл —
   прикріплений напряму `.html` Classroom/Drive показують як текст, а не
   виконують як сторінку.

На цьому етапі файл уже повністю робочий у режимі самоперевірки (без
передачі відповідей нікуди) — можна одразу давати посилання глядачам
YouTube чи використовувати для власного тестування.

## Крок 2. Коли потрібна студентська версія — підключити Google Таблицю

Виконується окремо, у будь-який час, незалежно від Кроку 1.

1. Створіть нову Google Таблицю (або відкрийте наявну для цієї лабораторної).
2. **Extensions → Apps Script** — обов'язково зсередини цієї Таблиці (не
   окремий standalone-проєкт: інакше `SpreadsheetApp.getActiveSpreadsheet()`
   поверне `null`, і запис у Таблицю мовчки не спрацює).
3. Видаліть шаблонний код і вставте вміст `apps-script-collector-<task>.gs`
   для цієї лабораторної.
4. **Deploy → New deployment** → тип «Web app» → Execute as: **Me**,
   Who has access: **Anyone**. Скопіюйте отриманий `/exec`-URL.
5. Перевірте URL в анонімному/інкогніто-вікні браузера (без входу в
   Google-акаунт) — це підтверджує, що доступ дійсно анонімний, а не лише
   для вас.

## Крок 3. Вставити URL у HTML — прямо на GitHub

1. Відкрийте файл лабораторної в репозиторії на GitHub, натисніть ✎
   (редагувати).
2. Знайдіть блок **DEPLOY CONFIG** на початку `<script>` (одразу після
   `TASK`) і вставте `/exec`-URL у поле `endpoint`.
3. Там же, за потреби, підправте межі генерації параметрів
   (`paramRanges`) чи ключ доступу викладача (`key`) — це той самий блок.
4. Збережіть (Commit changes) — файл одразу стає студентською версією для
   всіх, хто відкриє посилання.

Щоб повернути файл у режим самоперевірки — просто очистіть `endpoint` тим
самим способом.

## Оновлення коду збирача (`.gs`) пізніше

Якщо `answerFields` лабораторної зміняться — вставте новий код `.gs` у той
самий Apps Script проєкт і опублікуйте **Deploy → Manage deployments →
редагувати наявний деплой → New version** (НЕ «New deployment» — це
змінило б `/exec`-URL, і вже вставлений у HTML URL перестав би працювати).

## Діагностика

- Тестування Таблиці **ніколи не працює в чаті** з Claude (мережевий
  sandbox блокує fetch-запити) — це очікувано, перевіряти лише у
  завантаженому `.html`, відкритому у звичайному браузері.
- Якщо в Таблиці з'являється видимий рядок з текстом `ERROR: ...` —
  це не баг, а механізм підтвердження за задумом: оскільки запити йдуть
  через `mode:'no-cors'`, браузер студента ніколи не бачить, чи `doPost`
  реально відпрацював на сервері, тож `apps-script-collector-*.gs`
  навмисно пише видиму помилку в Таблицю замість тихого відмовлення.
  Найчастіші причини: невідповідність ключа (`SHEET_KEY` в HTML ≠
  `ACCESS_KEY` в `.gs`) або застаріла опублікована версія деплою.
- Детальніша діагностика: Apps Script → Executions (⏱ у лівому меню) —
  показує реальні помилки виконання; або вкладка Network (не Console!) у
  DevTools студента — там видно фактичний HTTP-статус і текст, який
  повернув `doPost`.
